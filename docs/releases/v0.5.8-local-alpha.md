# v0.5.8 Local Alpha Release Notes

Status: planned alpha release.

`v0.5.8 Local Alpha` is the first release intended for a technical user to run
end to end on their own machine. It is local-only and bring-your-own-key
instead of a hosted demo.

## Who This Is For

This alpha is for a user who can run Docker Compose, provide an OpenAI API key,
and point the application at a local Python repository. It is also suitable for
reviewers who need inspectable product evidence without relying on a free hosted
service.

It is not a managed SaaS deployment. There is no production authentication,
multi-tenant isolation, managed persistence, or free Render-style deployment in
scope for this release.

## What Is Included

- Local Docker Compose stack for React, FastAPI, Qdrant, and PostgreSQL.
- BYOK model access through `OPENAI_API_KEY` in `.env.local`.
- Direct RAG and bounded agentic repository research.
- API root redirect to FastAPI Swagger UI at `http://localhost:8000/docs`.
- Versioned OpenAPI contract at `docs/api/openapi.json`.
- Admin monitoring route for persisted run telemetry and feedback.
- Admin evaluation route for answer-judge results and search-evaluation
  highlights.
- Evaluation contexts split by repository or dataset so unrelated sources are
  not mixed.
- Qdrant dense, sparse, and hybrid retrieval paths.
- Local documentation for setup, usage, architecture, evaluation metrics, and
  monitoring KPIs.

## Local BYOK Path

```bash
cp .env.example .env
cp .env.local.example .env.local
# edit .env.local and set OPENAI_API_KEY
make install
make stack-up
```

Open `http://localhost:3000`, ingest a repository, ask one direct RAG question,
ask one agentic research question, and submit feedback.

Useful local routes:

| Route | Purpose |
|---|---|
| `http://localhost:3000` | Primary repository research workflow. |
| `http://localhost:3000/monitoring` | Local admin/operator monitoring dashboard. |
| `http://localhost:3000/evaluations` | Local admin/operator answer and search evaluation view. |
| `http://localhost:8000` | Redirects to Swagger UI. |
| `http://localhost:8000/docs` | Interactive API documentation. |
| `http://localhost:8000/openapi.json` | Runtime OpenAPI JSON. |

## Search Evaluation Highlights

The `/evaluations` page now surfaces curated search-evaluation highlights even
when no answer-judge rows have been persisted yet. This lets a local alpha user
see the retrieval baseline before running paid answer evaluation.

The highlighted baseline comes from the versioned held-out dataset and the
reproducible CLI path:

```bash
make evaluate-retrieval
uv run repo-research evaluate-retrieval --dataset eval/held_out.json \
  --output eval/results/retrieval-held-out.json
```

Generated reports under `eval/results/` remain local artifacts. Only curated
summary measurements are copied into documentation and UI highlights.

## Qdrant Text Versus Vectors

Qdrant stores one point per parsed repository chunk.

| Point field | What it contains | Why it matters |
|---|---|---|
| Point ID | Deterministic chunk ID. | Allows idempotent replacement by repository commit. |
| Payload | Full `ParsedChunk` JSON, including `content`, path, symbol, line range, repository, commit, chunk type, and metadata. | Lets the application reconstruct cited evidence text and metadata. |
| `dense` vector | Dense embedding generated from `ParsedChunk.content`. | Supports semantic search. |
| `sparse` vector | Sparse lexical encoding generated from the same text. | Supports keyword-style search. |

The source text is not stored inside the vector. It is stored as Qdrant payload
beside the named vectors. Dense search queries the `dense` vector, sparse search
queries the `sparse` vector, and hybrid search combines bounded dense and sparse
candidates with Qdrant Reciprocal Rank Fusion.

## Admin Surfaces

Monitoring and evaluation are local admin/operator evidence views. The UI marks
them as admin routes and uses lock icons to signal operator intent, but those
icons are not production authorization. Production auth and route gating are
explicitly outside this local alpha.

Use these views to inspect:

- persisted direct and agentic runs;
- latency, retrieval volume, cost, feedback, and error KPIs;
- answer-evaluation scores persisted to PostgreSQL;
- search-evaluation highlights from the curated held-out retrieval baseline.

## Demo Recording Guidance

Target length: 90 to 150 seconds.

Suggested flow:

1. Start at the README and show the local-only BYOK scope.
2. Run `make stack-up` or show the stack already running.
3. Open the app at `http://localhost:3000`.
4. Ingest a local repository.
5. Ask one direct RAG question and point to evidence citations.
6. Switch to agentic research for one change-impact question.
7. Submit feedback.
8. Open `/monitoring` and show local run telemetry.
9. Open `/evaluations` and show search highlights plus answer scores when
   available.
10. Open `http://localhost:8000/docs` to show Swagger/OpenAPI.

Do not expose `.env.local`, terminal history containing secrets, full API keys,
or private repository content that should not appear in a demo.
