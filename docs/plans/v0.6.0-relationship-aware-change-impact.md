# v0.6.0 Relationship-Aware Change Impact Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Improve change-impact completeness by expanding semantically retrieved evidence through a bounded, commit-scoped repository property graph.

**Architecture:** Ingestion builds an immutable JSONL property-graph artifact beside the Qdrant index. Qdrant continues to find starting evidence; research maps those chunks to graph nodes, traverses at most two hops, resolves related nodes back to canonical Qdrant chunks, and exposes only those validated chunks as evidence.

**Tech Stack:** Python 3.12, `ast`, Pydantic v2, JSONL, Qdrant, PydanticAI, pytest, Ruff, mypy

**Spec:** `docs/PRD.md` sections 21–27, especially section 22

## Global Constraints

- Keep one bounded PydanticAI research agent; do not add multi-agent orchestration.
- Keep Qdrant responsible for searchable chunks and embeddings.
- Store topology as versioned `manifest.json`, `nodes.jsonl`, and `edges.jsonl`; do not store it in PostgreSQL.
- Use stable string IDs, uppercase relationship types, scalar properties, deterministic ordering, and a separately versioned graph schema.
- Traverse at most two hops with relationship, confidence, and result-count bounds.
- Resolve every expanded node back to a canonical chunk for the same repository and commit before citing it.
- Do not claim compiler-grade call-graph completeness.
- Add no production dependency; use the standard library and existing packages.
- Preserve synchronous CLI/API contracts and explicit direct/agentic evaluation modes.
- Do not modify `eval/held_out.json` to improve results.
